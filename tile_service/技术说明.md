# 切片服务技术说明

日常启动和存储位置见 [使用说明](README.md)。本文保留配置、接口、处理规则与排障细节。

Windows 后端保管完整快照和正式产物。此服务只通过 HTTP 取得固定版本输入，使用 Linux 自己的 SQLite 队列串行切片，再交付 ZIP。两端不共享 SQLite。运行数据默认在 `~/.local/share/city-tile`，不要设置为 `/mnt/d` 或 Windows 数据库目录。

## 安装与启动

Windows 已安装 Ubuntu 和下述依赖后，在仓库根目录执行：

```powershell
.\tile_service\start.ps1
# 安全停止此脚本管理的服务
.\tile_service\start.ps1 -Stop
```

首次显式运行启动脚本时，生成已被 Git 忽略的 `map_back/storage/tile-service.json`：服务地址 `http://127.0.0.1:18744`、后端地址 `http://127.0.0.1:8000` 和 32 字节随机令牌。已有配置不覆盖；使用自定义后端存储时，先设置与后端一致的 `MAP_STORAGE_DIR`。脚本通过配置文件路径传值，令牌不进入命令行或启动输出。后端与 WSL 各自读取同一份配置，环境变量仍优先；修改配置后重启两端。请不要把该配置提交到版本库。

窗口保持隐藏，Windows 启动进程记录和标准输出/错误日志保存在同一 storage 目录；Linux 服务 PID 记录保存在 `CITY_TILE_DATA`（默认 Linux 数据目录）。停止时先核对 Linux PID 的启动时间、可执行文件、服务命令和配置路径，再发送 SIGTERM；Windows 启动进程也须通过 PID、创建时间及命令路径核对。记录身份不匹配时拒绝停止，不使用通配进程终止。只管理由本脚本启动的服务；手动启动的服务应在原终端停止。

后端启动后会为符合条件的本地 GeoJSON 自动补排任务；新上传完成正式索引后自动排队。切片成功发布、完整快照核验通过后，上传原文件保留七天，后端启动时补查并在北京时间每日 03:00 清理。切片失败时保留原文件并使用视野接口，完整数据与正式显示产物不随上传文件到期删除。

首次安装依赖仍在 Ubuntu 内执行：

```bash
cd /mnt/d/city
bash tile_service/install.sh
```

安装完成后回到 Windows 使用 `start.ps1`。若需要在 Ubuntu 前台运行和查看日志，可使用已生成的配置：

```bash
CITY_TILE_CONFIG=/mnt/d/city/map_back/storage/tile-service.json bash tile_service/start.sh
```

不使用共享配置文件时，仍可手动设置 `CITY_TILE_TOKEN` 和 `CITY_TILE_BACKEND_ORIGIN` 后运行 `start.sh`。

安装脚本需要 sudo，用于安装编译依赖。固定 Felt tippecanoe `2.79.0`，源码提交 `68ab8dcc229f95b8b25877697d5e8d66783af503`；运行前再次检查工具版本。Python 直接依赖固定在 requirements.txt。服务复用 `map_back/app/geojson_stream.py`、`road_style.py`、`poi_style.py`，启动脚本配置 PYTHONPATH，部署时需同时携带这些文件。

`CITY_TILE_HOST` 默认 `127.0.0.1`，`CITY_TILE_PORT` 默认 `18744`，`CITY_TILE_DATA` 更改 Linux 工作目录，`CITY_TILE_TIPPECANOE` 可指定固定版本二进制的绝对路径。只启动一个进程（`--workers 1`），不要使用 reload。停止时按 Ctrl+C 或发送 SIGTERM。当前子进程会终止；重启后中断任务清理并自动重试一次，第二次中断记为 failed。排队任务保持原顺序。

默认 Windows 流式推送，无需 WSL 回连 Windows。仅使用可选拉取模式时，NAT 模式应把 backend origin 配置为 Windows 在 WSL 可达的地址，Windows 后端的监听和防火墙须允许该连接。服务监听范围也应仅允许 Windows 后端访问。内部令牌不发给浏览器，不写入命令日志。

## HTTP 契约

`GET /health` 公开，返回服务状态、worker_alive、recipe 和固定工具版本。所有 `/internal/` 路由都要求 `Authorization: Bearer <CITY_TILE_TOKEN>`。

- `POST /internal/jobs`：`{key,source_url,source_mode:"push",profile,asset_id,version:"1.0.0",recipe:"geojson-v2",retry:false}`。profile 为 roads/poi/generic，version 保留版本字符串。相同 key 的活动或成功任务返回同一 id；不同内容复用相同活动 key 返回 409。失败或取消后，只有显式 retry:true 才创建新尝试。
- `PUT /internal/jobs/{id}/source`：Windows 主动流式推送已标识 FeatureCollection，携带相同令牌和 `X-Snapshot-Sha256`、`X-Feature-Count`。支持 chunked Transfer-Encoding。在完整接收并原子落盘前不执行任务；GET/POST 响应的 needs_source=true 表示需要发送。重复成功推送不会重写已接收输入；断流后可重发。Windows 到 WSL 已可达时，无需允许 WSL 主动连接 Windows，也无需修改 Windows 防火墙。
- `GET /internal/jobs/{id}`：返回 id、status、stage、error、artifact_sha256、artifact_bytes、acknowledged。状态为 queued/running/succeeded/failed/cancelled；不提供估计百分比。error 保留末尾最多 12,000 字符和切片失败日志。
- `POST /internal/jobs/{id}/cancel`：取消排队/执行中的任务，并终止对应整个切片进程组。已成功任务保持成功。
- `GET /internal/jobs/{id}/artifact`：成功后的 application/zip，ETag 为 ZIP SHA256。支持传输后重取，直到确认清理。
- `DELETE /internal/jobs/{id}/artifact`：Windows 完成校验、原子发布后确认接收，清理服务端全部产物。重复确认安全。失败或取消任务也可确认清理。

source_url 必须严格匹配已配置的 backend origin 和 `/internal/render-source/{asset_id}/{version}`，禁止用户名、密码、查询参数及重定向。source_mode=push 时不访问此 URL；未指定 source_mode 时兼容 pull 模式，下载带相同 Bearer 令牌，要求响应头 `X-Snapshot-Sha256`（正式快照 SHA256）、`X-Feature-Count`，并验证处理数量。输入为流式 FeatureCollection，每个 feature 有顶层 `__object:{object_id:string,feature_index:integer}`；保留原始索引，不按处理顺序创建新身份。

## 产物与身份

ZIP 使用 ZIP_STORED 避免重复压缩 PMTiles，包含 `map.pmtiles`、`manifest.json`，道路额外包含 `road_sources.jsonl`。manifest 包含源资产/版本、profile、recipe、正式快照摘要、要素数量、身份摘要、图层 data、z0–16、bounds、工具版本、制图参数、PMTiles SHA256，以及属性字节/顶点/显示要素/工作空间体积统计。身份摘要按源流顺序，对 UTF-8 JSON 紧凑数组 `[object_id,feature_index]` 加换行，逐条 SHA256。工作空间统计为阶段采样，不代表操作系统级精确峰值。

MVT properties 强制写入 object_id、feature_index。道路还有 road_rank（0–3；不支持的道路类别为99，由显示端过滤）、road_class、name、display_group_id；POI 有 poi_category、priority、name、background_eligible、max_scale（-1 表示不限尺度），显式 importance/weight/priority 中首个有限数值规范为 weight。完整原属性与几何只保存在 Windows 正式快照；此处白名单裁剪及六位小数只作用于显示副本。

道路兼容规则直接复用后端的名称/编号/桥隧/层级/单行方向签名，仅在原始端点度数为 2 时串联；使用 SQLite 暂存几何，内存只保留端点/签名/身份元数据。连续组使用稳定哈希 ID，映射逐行写为 `{group_id,source_object_ids:[...]}`，tile 的 display_group_id 对应 group_id。单组几何超过 64 MiB 明确失败，不截断来源。MultiLineString 保留其原始 object_id，不与不同对象合并。普通面不合并。来源明细由后端按点击位置还原。

几何修复后降至六位小数并去除连续重复点，再检查类型、空值、塌缩和坐标范围；错误包含源对象 ID。超出 Web Mercator 纬度覆盖范围时失败，避免静默漏对象。POI 中文分类复用后端逻辑；保留候选，不使用 tippecanoe 默认点丢弃，精确尺度和优先级由显示端处理。

基础切片配置为 `-Z0 -z16 -r1 --buffer=5 --maximum-tile-bytes=2097152 --no-feature-limit --no-tiny-polygon-reduction --detect-shared-borders`。道路及包含显式道路的 generic 混合产物增加 `--no-line-simplification --full-detail=12 --low-detail=12 --minimum-detail=12`，避免削掉转折或因瓦片体积而降低坐标精度；manifest 的 `contains_roads=true` 标识此路径。纯 POI、纯面等产物继续使用 `--simplify-only-low-zooms`。

瓦片大小上限为 2 MiB，道路保真参数下超限即失败，禁止随机丢道路、合并不同普通面对象或降低精度来凑预算。道路最小层级 0/9/11/13 在 Web Mercator 高纬边界保守放行，前端再按实际米/像素和用户等级筛选。发布前用同版本 tippecanoe-decode 流式核验 z16 的所有显示身份，缺失或身份变化均失败。解码临时文件仅用于审计，随后清理。

含道路的产物在当前显示精度下超过 64 个瓦片、2,000 个要素、100,000 个顶点或 10 MiB 显示预算时，直接回退保真视野接口；不继续读取更粗层级。视野接口先按等级选择完整道路组，仅裁剪并清理完全重复坐标，不削减道路转折。generic 显式道路也参与兼容连接，存在来源映射时 ZIP 同时携带 `road_sources.jsonl`，普通非道路线不参与道路合并。

本次制图版本为 `geojson-v2`，旧版入口不再提供地图显示。后端自动为既有资产版本排入新版任务；从完整快照读取输入，继承原有首次发布时间、原文件到期时间和已清理状态。升级时先重启切片服务，再重启后端并刷新前端。

源输入完成预处理后立即删除；任务结束清理所有中间 JSONL、SQLite、PMTiles 和日志，仅留下待确认 ZIP。Windows 确认后删除 ZIP。确认丢失时 Windows 应重取/重新确认，重启对账保留未确认成功 ZIP。服务不自行按时间删未确认产物，避免传输竞态；应监控未确认任务的空间。磁盘不足导致 failed，Windows 不得发布半成品。输入正规化传输限制 4 GiB（源上传上限仍由 Windows 控制）。建议预留源数据及显示 spool、切片临时文件与最终 ZIP 的空间，按真实数据采样统计留足余量。

## 定向验证

`start.ps1` 保存为带 BOM 的 UTF-8，兼容 Windows PowerShell 5.1 对中文脚本的解码。编辑时保留该编码标记；PowerShell 7 也可运行。Windows 入口解析回归检查在项目根目录执行：

```powershell
.\map_back\.venv\Scripts\python.exe -m unittest tile_service.tests.test_powershell -v
```

```bash
cd /mnt/d/city
export PYTHONPATH="$PWD/map_back:$PWD"
export PATH="$HOME/.local/bin:$PATH"
~/.local/share/city-tile-venv/bin/python -m unittest tile_service.tests.test_service
# HTTP 测试额外依赖，仅开发时安装
~/.local/share/city-tile-venv/bin/pip install httpx==0.28.1
~/.local/share/city-tile-venv/bin/python -m unittest tile_service.tests.test_http
```

HTTP 测试实际运行固定工具、流式下载、校验 PMTiles/manifest/来源映射并确认清理。Windows–WSL 实际传输及接近 1 GiB 的派生混合点线面样本已完成隔离联调。测试记录见本轮待办文档；真实浏览器中的地图观感仍需人工复核。
