# 前后端功能清单与验收标准

**P0** = 六周内必须，**P1** = 有余力再做。数据层（广州 CBD 转换）先按你的要求跳过，验收全部用现有资产和一份合成路网样例 `net-001` 也能跑完。

---

## 一、前端（B）应该有什么

### 1. 场景与视角（P0）

| 功能点 | 要求 | 验收点 |
|---|---|---|
| 资产加载 | 按 `asset_id@version` 加载 3D Tiles，有加载进度和失败原因 | 故意给错 URL，页面显示“资产不存在/加载失败 + trace_id”，不能白屏 |
| 初始视角 | 进入即定位到资产包围范围，不出现“模型在天上/地下” | 刷新后视角可恢复（URL 参数或本地存储） |
| 导航 | 旋转、缩放、倾斜、复位、二维/三维切换、指北 | 复位后回到初始包围范围，误差可接受 |
| 坐标与比例 | 鼠标位置显示经纬度/高程、比例尺 | 读数与 Cesium 拾取一致 |
| 区域定位 | 内置示范区域列表（香港维港、广州珠江新城、校区） | 点一下能飞到该区域，失败有提示 |

### 2. 图层树（P0）

| 功能点 | 要求 | 验收点 |
|---|---|---|
| 分类树 | 底图、建筑、道路、水体、专题（点/线/面）、仿真结果分组 | 树结构与接口返回一致 |
| 显隐/透明度 | 开关立即生效，透明度 0–1 | 拖动透明度时画面同步变化 |
| 顺序 | 上移/下移改变叠加顺序 | 刷新后顺序保持 |
| 图例 | 每个专题图层带图例与单位 | 图例单位与数据一致（米/个/℃） |
| 计数 | 图层要素数量 | 与 `/api/objects` 统计一致 |

### 3. 时间维度（P0，新增需求）

| 功能点 | 验收点 |
|---|---|
| 时间轴：范围、当前时刻、步进 | 拖动后场景/专题图层按时间刷新 |
| 播放/暂停/速率（1×/2×/5×） | 播放时时间标签连续推进，暂停即停 |
| 时次切换（逐小时/逐日） | 切换后属性面板显示对应时次数据 |
| 同视角前后对比（分屏或滑动） | 两侧相机联动，同一位置可对照 |
| 缺测提示 | 该时次无数据时显示“缺测/未覆盖”，**不能画成 0** |
| 静态图层行为 | 静态图层切换时间时不闪、不重复加载 |

### 4. 对象查询（P0）

- 点击建筑/道路/点要素 → 高亮 + 右侧详情：`object_id`、类型、名称、高度/等级、来源（模型/OSM/人工）、置信度、坐标、所属图层版本。
- 列表与地图联动：列表点选 → 地图定位并高亮；地图点选 → 列表滚动到对应行。
- 框选/多边形选择 → 返回要素集合与计数（可与统计联动）。
- **3D Tiles 无属性时**：明确显示“该瓦片未携带语义属性，来源：几何模型”，不能留空或假装有值。

### 5. 数据管理页（P0）

- 上传：进度条、取消、失败原因（413/422 具体到“路径含反斜杠/缺少 tileset.json/超出 2 GiB”）。
- 登记：外部文件/URL 登记（大文件不上传），填名称、类型、来源、坐标说明。
- 列表：分页、按类型/状态/时间筛选、按体积排序。
- 详情：体积、文件数、校验和、坐标范围、版本、状态、入口路径。
- 删除：被场景/运行引用时返回 409 并说明“被 3 个场景引用，先解除”。
- 统计：总容量、各类型数量、最近 7 天新增。

### 6. 仿真推演页（P0，核心）

| 功能点 | 要求 | 验收点 |
|---|---|---|
| 场景配置 | 选路网版本、设起点/终点、勾选阻断边（点地图道路或列表） | 参数可保存为场景，刷新后还在 |
| 提交运行 | 显示 run_id 与状态（排队/运行中/成功/失败），支持取消 | 重复点提交不会产生两条记录（幂等） |
| 结果对比 | 基准 vs 阻断：路径、总长（米）、预计时间、绕行或不可达 | 660 m → 960 m（+45.5%）显示与后端一致 |
| 地图呈现 | 基准路径（蓝）、阻断后路径（橙）、阻断边（红叉） | 三者与结果 JSON 的节点序列一致 |
| 回放 | 按步/按时间播放车辆或状态变化 | 可暂停、可拖动、可复位 |
| 导出 | 结果 JSON/GeoJSON 下载 | 文件内容与页面显示一致 |

### 7. 记录与可复现（P0）

- 运行历史：按场景/状态/时间筛选，查看详情、重跑（同参数生成新 run）。
- 书签：保存视角 + 图层状态 + 场景。
- **URL 可复现**：`?scene=s1&run=r1&t=2026-10-25T12:00` 分享后，别人打开看到同一画面。

### 8. 异常与空态（P0）

- 统一错误提示：`code + message + trace_id`，可复制。
- 网络断开：顶部提示“连接中断，正在重试”，恢复后自动刷新。
- 空数据：区分“无数据”“加载失败”“无权限”三种文案。

## 二、后端（C）应该有什么

### 1. 接口清单

现有 `layers/assets/bookmarks/health` 保留，新增以下资源：

| 资源 | 接口 | 说明 | 关键约束 |
|---|---|---|---|
| 版本 | `GET /api/version` | 服务版本、模型版本、数据版本 | — |
| 资产 | `POST /api/assets/register` | 登记路径/URL，不搬文件 | 重复登记返回 409 |
| | `GET /api/assets` | 分页、筛选 | 支持 `type/status/q` |
| | `GET /api/assets/{id}` | 详情含 `sha256`、`bounds`、`status` | 404 明确 |
| | `DELETE /api/assets/{id}` | 删除文件与记录 | 被场景/运行引用 → 409 |
| | `GET /api/assets/{id}/download` | 打包下载 | 内容与本机一致（sha256 校验） |
| 对象 | `GET /api/objects` | 按 `asset_id`、bbox、类型、关键词、时间查 | 分页、bbox 必须真实裁剪 |
| | `GET /api/objects/{id}` | 单对象含几何与属性 | 属性为空要返回 `semantic_source` |
| | `GET /api/objects/summary` | 按类型/面积/高度统计 | 与逐条查询结果一致 |
| 场景 | `POST /api/scenes` | 存相机、图层、路网版本、参数 | 返回版本号 |
| | `PUT /api/scenes/{id}` | 乐观锁（`If-Match` 版本） | 版本冲突 → 409 |
| | `GET /api/scenes/{id}` | 完整配置 | — |
| 路网 | `GET /api/networks`、`GET /api/networks/{id}` | 节点、边、权重、坐标系 | 版本不可变 |
| | `POST /api/networks/{id}/validate` | 连通性、孤立点、重复边 | 返回问题列表 |
| 仿真 | `POST /api/runs` | 提交运行，支持 `Idempotency-Key` | 同 key 返回同一 run_id |
| | `GET /api/runs` | 列表与状态过滤 | — |
| | `GET /api/runs/{id}` | 状态、耗时、错误 | 重启后可读 |
| | `POST /api/runs/{id}/cancel` | 取消排队/运行中 | 已结束 → 409 |
| | `GET /api/runs/{id}/result` | 基准/阻断路径与指标 | 结果不可变 |
| | `GET /api/runs/{id}/download` | 结果 JSON/GeoJSON | — |
| 时序 | `GET /api/layers/{id}/times` | 可用时次列表 | 无数据 → 空数组 |
| | `GET /api/timeseries` | 按 bbox/时次查专题值 | 缺测返回 `missing: true` |
| 统计 | `GET /api/stats/overview` | 资产/对象/运行数量与容量 | — |

### 2. 运行状态机

```
queued → running → succeeded
              ↘ failed（可重试，重试生成新 run，不覆盖旧记录）
              ↘ cancelled
```

- 每个 run 记录：`run_id`、`inputs_sha256`、`model_version`、`data_version`、`submitted_at/started_at/finished_at`、`error`、`trace_id`。
- 超时、异常进程被杀后，重启时把 `running` 标为 `failed` 并写原因（不能永久卡住）。
- 结果只读，不允许 PUT 覆盖。

### 3. 存储布局

```
data/uploads/{asset_id}/{version}/...
data/runs/{run_id}/input.json
data/runs/{run_id}/result.json
data/runs/{run_id}/run.log
```

- 启动时扫描目录，与数据库对账（现有 `reconcile` 可复用到 runs）。
- `assets` 与 `scenes`、`runs` 之间用 `asset_id@version` 引用，不存绝对路径。

### 4. 统一错误与边界

- 返回结构：`{"code": "ASSET_IN_USE", "message": "...", "detail": {...}, "trace_id": "..."}`。
- 400 参数、404 不存在、409 冲突、413 超限、422 内容不合规、500 未预期（必须带 trace_id 可查日志）。
- 上传/下载必须防目录穿越、拒绝绝对路径、反斜杠、符号链接、加密 ZIP（现有校验保留）。

## 三、最小 JSON 契约（前后端先冻结这个）

**运行请求**
```json
{"scene_id":"s1","network":{"asset_id":"net-001","version":"1.0.0"},
 "origin":"S","destination":"T","blocked_edges":["B-T"],
 "params":{"mode":"car"},"seed":0}
```

**运行记录**
```json
{"run_id":"run-20261025-0001","status":"succeeded",
 "submitted_at":"2026-10-25T12:00:00+08:00",
 "finished_at":"2026-10-25T12:00:01+08:00",
 "inputs_sha256":"...","model_version":"dijkstra-undirected-v1",
 "data_version":"net-001@1.0.0","error":null}
```

**运行结果**
```json
{"run_id":"run-20261025-0001",
 "baseline":{"path":["S","A","B","T"],"length_m":660,"reachable":true},
 "blocked":{"path":["S","A","C","D","T"],"length_m":960,"reachable":true},
 "metrics":{"increase_percent":45.45,"rerouted":true},
 "created_at":"2026-10-25T12:00:01+08:00"}
```

字段名冻结后，前端可以先用 mock 数据把页面跑起来，后端按同一份 schema 实现，避免“等接口”。

## 四、怎么验收

### A. 单接口验收（每个接口都绑这几类用例）

| 用例类型 | 例子 | 通过标准 |
|---|---|---|
| 正常 | `POST /api/runs` 阻断 B–T | 201，返回 run_id；轮询后 succeeded，`blocked.length_m=960` |
| 幂等 | 同一 `Idempotency-Key` 连发两次 | 两次返回同一 run_id，数据库只有 1 条 |
| 非法输入 | 阻断边不存在 | 422 + `code=INVALID_EDGE`，不产生 run |
| 不可达 | 起终点不连通 | succeeded，`baseline.reachable=false`，不是 500 |
| 冲突 | 删除被场景引用的资产 | 409 + 引用列表 |
| 重启 | 提交后杀进程再启动 | run 状态可读，running 被标 failed |
| 追溯 | 同输入跑两次 | `inputs_sha256` 相同，结果相同 |

### B. 页面验收（逐条“操作 → 预期”）

1. 打开工作台 → 3 秒内出现场景与图层树；错误时显示原因 + trace_id。
2. 关闭“建筑”图层 → 建筑消失，刷新后仍关闭。
3. 拖动透明度到 0.5 → 建筑半透明，图例不变化。
4. 时间轴拖到 08:00 → 专题层显示 08:00 的值；拖到无数据时次 → “该时次缺测”，不显示 0。
5. 点一栋建筑 → 高亮 + 详情含 `object_id`、来源、置信度。
6. 数据页上传一个 300 MB 3D Tiles ZIP → 进度到 100%，列表出现记录，体积/文件数正确。
7. 上传一个路径含反斜杠的 ZIP → 422，提示具体原因。
8. 推演页设 S→T、勾选 B–T 阻断 → 提交后状态从排队变成功；结果条显示 660→960 米、+45.5%。
9. 地图上蓝/橙/红三色与结果 JSON 的节点序列一致。
10. 点“导出” → 下载 JSON，内容与页面一致。
11. 复制当前 URL 到新窗口 → 同一场景、同一 run、同一时间点。
12. 断开后端服务 → 页面提示连接中断；恢复后自动重连成功。

### C. 端到端演示脚本（5 分钟，固定路径）

| 步 | 操作 | 通过标准 |
|---|---|---|
| 1 | 打开页面，进入“香港维港” | 场景加载完成，图层树完整 |
| 2 | 关闭水体、调整建筑透明度 | 画面即时变化 |
| 3 | 点击一栋建筑 | 详情含来源与置信度 |
| 4 | 数据页上传/登记一份资产 | 状态 `ready`，体积正确 |
| 5 | 推演页配置 S→T + 阻断 B–T，运行 | 结果对比正确，可回放 |
| 6 | 导出结果 + 复制 URL 重开 | 数据一致、画面一致 |

### D. 非功能验收（建议指标，可按机器调整）

| 项 | 指标 | 怎么测 |
|---|---|---|
| 场景首屏 | ≤ 5 s（本地、现有资产） | Performance 面板记录 3 次取中位 |
| 图层切换 | ≤ 300 ms | 手动 + 控制台计时 |
| 对象查询 | 1 万对象 bbox 查询 p95 ≤ 200 ms | 100 次请求统计 |
| 仿真运行 | 10 万边路网 ≤ 2 s | 后端日志耗时 |
| 并发 | 5 个并发 run 不串结果 | 同时提交 5 个不同请求，核对 run_id 与结果 |
| 稳定性 | 连续运行 1 小时无内存暴涨 | 每 10 分钟记录 RSS |
| 可追溯 | 任一 run 可查输入、版本、耗时、日志 | 抽查 3 条 |
| 安全 | 上传/下载无路径穿越，无硬编码密钥 | 用 `..%2f`、反斜杠、绝对路径各试一次 |

### E. 8 维验收评分卡（对应仓库口径）

| 维度 | 通过标准 | 证据 |
|---|---|---|
| 数据可用 | 至少一份资产能加载、能定位、坐标正确 | 截图 + 资产记录 |
| 页面闭环 | 上传→登记→列表→详情→下载全通 | 演示录屏 |
| 对象交互 | 点选/框选/详情/联动可用 | 录屏 + 对象 ID 清单 |
| 场景浏览 | 导航/复位/区域定位/二维三维可用 | 操作记录 |
| 仿真正确性 | 基准/绕行/不可达三组手算一致 | 测试报告（含手算表） |
| 可追溯 | run 记录含输入哈希、模型版本、时间、日志 | 抽查记录 |
| 性能 | 上表指标达标 | 测量表 |
| 交接 | 另一人按文档从零跑通 | 交接记录 + 问题清单 |

### F. 交付物（缺一不算完成）

1. `openapi.json` + 一页接口说明（谁调、什么时候调、错误码）。
2. 测试报告：接口用例表、页面用例表、性能表、失败截图。
3. 5 分钟演示录屏（按 C 的脚本）。
4. 数据清单更新：资产 ID、版本、坐标、体积、校验和。
5. 运行记录样例 3 条（正常/绕行/不可达）。

## 五、B/C 的推进顺序（避免互相等）

1. **第 1 周**：C 冻结上述 4 个 JSON 契约 + 用合成数据出 mock 接口；B 用 mock 把图层树/对象详情/推演页跑起来。
2. **第 2 周**：接入真实资产接口（加载、列表、详情、下载），数据页完成。
3. **第 3 周**：对象查询 + 时间维度最小样例（点线面各一、2 个时次）。
4. **第 4 周**：仿真 run 全链路（提交 → 状态 → 结果 → 地图 → 回放）。
5. **第 5 周**：性能、错误路径、重启恢复、并发。
6. **第 6 周**：互验（B 验 C 的接口，C 验 B 的页面）、补文档、录屏。
