# 步骤23：自动重连、空态与综合统计

工作区统一跟踪API连接与健康探测。服务中断时顶部显示自动重试，延迟依次为1、2、5、10、30秒；正常连接每10秒检查一次。重叠失败合并为单次探测，晚到的旧健康结果不会覆盖新请求确认的连接状态。

## 恢复行为

- 目录、资产分页与详情、对象、时序、运行历史及已知运行自动读取。相机、筛选、页码、图层配置和仿真草稿保留。
- 静态就绪资源保留实例；失败资源重试加载。左右时间轴分别恢复读取。
- 保存、提交与画面恢复期间合并等待重连刷新；仿真目录恢复独立于视图scope，保持固定路网版本。
- 未知POST保留原错误、输入和幂等键，继续由“重试同一次提交”确认。自动恢复只读取运行。
- 无权限、读取失败和真实空数据区分显示；“请求诊断”支持复制code/message/trace_id。200响应头之后断流也归为带client trace的网络失败，解析错误使用`INVALID_RESPONSE`。

## 综合统计

展示资产、对象、运行、本地容量、类型和7天新增。进入数据页、重连和运行状态变化触发更新。列表与统计分别加载、分别显示错误；统计失败时清除旧统计，成功列表保持。

后端在SQLite显式读事务中计算整个统计响应。真实并发删除用例复现了旧实现“资产数为删除前、容量和对象数为删除后”的混合结果，新实现返回同一快照。

## 验证结果

整组实现后执行前端246项全量回归与生产构建；审查补充响应体断流后，4项连接生命周期用例通过。资产/数据页18项、仿真/历史41项和后端资产统计20项集中回归通过，最终构建通过。

真实Edge在隔离服务中完成两次断开/自动恢复：

1. 断开期间将草稿seed从77改为78，恢复后名称、seed、阻断B-T、场景ID/版本、相机保持。
2. 恢复未提交运行，已就绪源文件重载0次。
3. 服务接受运行后丢弃响应；再次断开恢复，原提交仍待确认，自动POST为0。手动重试前后幂等键和输入相同，两次POST返回同一运行，服务端总数增加1。
4. 路径结果660/960米，数据页对象149、运行2与接口一致；运行2包含流程准备阶段的已有记录。
5. 403显示“无权限查看图层登记”，连接状态保持在线。诊断文本含`ACCESS_DENIED`与`step23-permission-trace`，可复制。
