# 步骤16：引用保护与提示验收

2026-10-26，后端342项测试、前端160项测试和生产构建通过。本步新增13项后端用例、3项前端用例。

| 检查 | 结果 |
| --- | --- |
| 完整明细与分类计数 | 同一资产的两个版本分别被1个场景和1个运行引用，加1个图层，返回5条明细；message按1图层/1场景/1历史运行计数，ASSET_IN_USE及旧图层id/name形状保留 |
| 历史保护 | cancelled/failed/succeeded三种终态，分别验证删除场景、解除场景图层两种路径；全局登记移除后仍409，固定版本及源文件SHA保持 |
| 真实事务竞争 | 创建场景/运行与资产删除分别抢先，4组HTTP并发请求使用真实SQLite写事务；引用成功则删除409，删除先成功则后续场景拒绝；无悬空外键和文件丢失 |
| 路网与默认保护 | 场景删除后，历史运行的固定路网外键仍拒绝直接删除该版本；默认文件403且逐文件SHA不变 |
| 外部资产 | 有图层引用时409；释放后移除登记，未读取远端，现有本地文件与目录不变 |
| 页面 | 详情与删除冲突共用引用列表，显示类型、名称、ID、场景/快照版本与资产版本；提示各类引用的处理方式 |
| 重新登记 | 仅有场景/运行引用时允许重新登记；仍有图层登记时保持既有入口，缺文件或未知类型保持不可登记 |

真实Edge验收使用独立数据库、后端18000和前端15173，原8000服务保持运行。页面显示资产无引用后，后台新增图层、场景及运行，再点击确认删除：返回409，弹窗显示各1个引用、正式ID、版本和trace_id，确认按钮禁用。删除图层与场景后再次请求删除，返回1条历史运行引用；资产SHA-256保持、运行结果仍为960m。页面“重新登记”可用，实际保存后资产ID保持，引用变为图层和历史运行共2条。
