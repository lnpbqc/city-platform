# 开发说明

## 技术栈与开发环境

前端使用 Vue 3、TypeScript、Vite 和 CesiumJS；后端使用 FastAPI、SQLAlchemy、Alembic、SQLite、Shapely 和 pyproj。依赖及版本以 [package.json](../map/package.json)、[pyproject.toml](../map_back/pyproject.toml) 和对应锁文件为准。

使用 Node.js 24、pnpm、Python 3.13 和 uv。安装依赖、环境变量和双终端启动步骤统一见[部署说明](部署说明.md)。开发后端执行 `uv sync` 安装测试依赖，前端执行 `pnpm install --store-dir ..\.pnpm-store`；分别在 `map_back/`、`map/` 运行。

### 前端边界

`App.vue` 协调 `#/map`、`#/data` 和 `#/simulation`。地图页由 `MapWorkspace.vue` 管理，数据页由 `DataManagerView.vue` 管理，仿真页由 `SimulationWorkspace.vue` 管理。数据页可独立于 WebGL 工作，地图实例在页面往返时保留。

Cesium 对象由独立控制器管理，通过回调与 Vue 状态连接，避免进入深层响应式对象。资源异步加载完成时核对请求身份；图层移除、版本或校区切换后取消旧请求并丢弃过期结果。专题时间切换复用实体，静态资源复用实例。

`mapNavigation.ts` 管理相机约定，`buildingTerrain.ts` 处理白模地形采样，`workspaceState.ts` 与 `workspaceRoute.ts` 处理工作区快照和路由。组件私有样式位于 `.vue` 文件，全局样式和变量位于 `style.css`。

### 后端边界

`main.py` 组装路由、统一错误和启动流程。资产目录、指纹与下载分别由 `asset_catalog.py`、`asset_metadata.py`、`assets.py` 等模块处理；`object_index.py` 和 `object_queries.py` 提供固定版本对象索引与空间查询；`timeseries.py` 提供不可变时序快照。

`scenes.py` 管理场景和乐观锁，`networks.py` 校验路网版本，`routing.py` 计算路径。`runs.py` 提供运行 API，`run_store.py` 保存状态与哈希，`run_worker.py` 管理单进程持久队列及计算子进程，`run_artifacts.py` 管理输入、结果和日志镜像。

`models.py` 定义持久数据结构，Alembic 是唯一建表和迁移入口；应用启动补齐内置资产、对象索引、时序及合成路网，并启动队列。修改表结构时新增迁移，保留已有 ID、地址和固定版本引用。

## 接口与状态约定

- 后端业务契约位于 [contracts.py](../map_back/app/contracts.py)，图层、资产及收藏模型同时见 [schemas.py](../map_back/app/schemas.py)。字段以运行时 [OpenAPI](http://127.0.0.1:8000/openapi.json) 为准，行为约定见[接口说明](api_contract.md)。
- 图层登记、实体资产与地图加入状态分别管理；删除前按资产版本检查图层、场景和历史运行引用。
- 发布资产、路网和时序使用固定版本；场景使用递增版本及 `If-Match`，运行保存不可变输入快照和成功结果。
- 提交响应未知时，保留幂等键和原始请求重试；自动重连恢复读取，提交重试由用户触发。
- JSON 使用 UTF-8，时间带时区；UTC 用于接口交换，北京时间用于内置时序日均。未知值使用 `null`，数值 0 保持原值。

前端开发和构建预览均通过 Vite 将 `/api`、`/data-files` 代理到 `127.0.0.1:8000`。Cesium 的 Workers、ThirdParty、Assets、Widgets 由静态复制插件发布到 `/cesium/`，与 `CESIUM_BASE_URL` 保持一致。修改代理或静态路径时，同时检查开发和构建预览。

## 测试与构建

在 PowerShell 中执行：

```powershell
Set-Location D:\city\map_back
uv sync
uv run pytest -q

Set-Location D:\city\map
pnpm test
pnpm build
```

前端使用 Node.js 内置测试运行器和实验性模块替身 API；构建先执行 `vue-tsc -b`，再运行 Vite。后端测试使用临时数据库和文件目录，覆盖迁移、并发、资产安全、空间查询、场景与队列恢复。

白模生成逻辑的独立测试：

```powershell
Set-Location D:\city\map
uv run --project ..\map_back python -m unittest discover -s scripts -p test_campus_buildings.py
```

生成脚本会写入内置样例；仅检查文档或测试时保持样例原样。数据更新步骤见[数据与模型说明](数据与模型说明.md)。

### 核心手动验证

保持后端运行，执行 `pnpm preview --port 4173 --strictPort`，在 [4173](http://127.0.0.1:4173/) 验证：

| 流程 | 预期结果 |
| --- | --- |
| 首次地图、校区切换、导航、二维/三维 | 资源位置正确，显隐、透明度、视角和复位正常 |
| 数据页上传→加入→移除→重新加入 | 上传后先登记；移除地图保留文件；刷新可恢复状态 |
| 对象点选、列表分页、框选与多边形 | 地图与列表一致，范围高亮及统计来自同一选择集 |
| 时间切换、逐日、双视图 | 缺测与 0 区分，静态图层稳定，两侧相机联动 |
| 正常、B-T 阻断、S-A 阻断 | 分别为正常、960 米绕行、不可达，具体步骤见功能说明 |
| 历史重跑、回放与导出 | 原输入哈希保留，新运行 ID 生成，导出与结果一致 |
| 工作区收藏与复制链接 | 新页面恢复固定场景、图层、相机、时间与结果 |
| 场景冲突、引用保护、断线恢复 | 保留草稿，显示具体引用或诊断，重连恢复读取 |

使用临时上传数据验证删除流程，结束后通过页面解除引用并清理。历史运行会持续保护其资产版本，删除验证应使用未提交运行的临时资产。

### 性能复测

需要验证空间查询或寻路性能时，在 `map_back/` 执行：

```powershell
uv run python tools/verify_object_queries.py
uv run python tools/verify_routing.py
```

对象工具在临时存储与回环端口创建万对象样例，结果写入 `.verification/step08-performance.json`；寻路工具测量十万节点、十万边的校验、建图、两次寻路和结果重建，输出 JSON。阈值和当前机器结果以工具输出为准。
