# 部署说明

## 环境与目录

本文覆盖 Windows 本机单用户运行，使用 PowerShell，命令以项目位于 `D:\city` 为例。其他位置替换该路径，并保持 `map/`、`map_back/` 为同级目录。

准备 Node.js 24、pnpm、Python 3.13 和 uv。首次安装依赖需要联网；在线底图、Cesium 地形和行政区边界也依赖网络。浏览器需支持 WebGL。

后端读取 `map/public/samples/` 和 `map/src/data/` 的内置资源，迁移或复制项目时保留完整前后端目录。`map/docs/research/` 的原始快照供离线生成白模和相关测试使用。

## 首次启动

### 1. 启动后端

打开第一个 PowerShell 终端：

```powershell
Set-Location D:\city\map_back
uv sync --no-dev
uv run --no-dev alembic upgrade head
uv run --no-dev uvicorn app.main:app --host 127.0.0.1 --port 8000
```

首次安装和升级代码后执行迁移，应用启动前需已有业务表。后端采用单个 uvicorn 服务进程，每次模型计算使用独立子进程；保持上述单进程启动方式。

在另一个终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

预期返回 `status: ok`。接口入口为[交互文档](http://127.0.0.1:8000/docs)和[OpenAPI JSON](http://127.0.0.1:8000/openapi.json)。

### 2. 配置并启动前端

打开第二个 PowerShell 终端：

```powershell
Set-Location D:\city\map
pnpm install --store-dir ..\.pnpm-store
if (-not (Test-Path -LiteralPath .env.local)) {
    Copy-Item -LiteralPath .env.example -Destination .env.local
}
# 编辑 .env.local，选择底图来源并配置对应的 Key 或 Token。
pnpm dev --port 5173 --strictPort
```

浏览器打开[地图工作台](http://127.0.0.1:5173/)。在 `map/.env.local` 中选择底图来源：

| 配置项 | 说明 |
| --- | --- |
| `VITE_BASEMAP_PROVIDER` | `cesium` 或 `tianditu`，未设置时使用 `cesium`，保持原有行为 |
| `VITE_TIANDITU_KEY` | 天地图浏览器端 Key，仅天地图模式使用 |
| `VITE_CESIUM_ION_TOKEN` | 具备影像和地形权限的浏览器只读 Token，仅 Cesium 模式使用 |

使用天地图时，在[天地图开发资源](https://lbs.tianditu.gov.cn/)注册并登录，在控制台创建浏览器端应用、申请 Key，按控制台要求配置访问域名，然后填写：

```dotenv
VITE_BASEMAP_PROVIDER=tianditu
VITE_TIANDITU_KEY=你的天地图Key
```

天地图模式加载卫星影像与中文地名注记，使用椭球地表；即使配置了 ion Token，也不会请求 ion 影像或地形。两层共同响应底图显隐、透明度和移除操作。未填写 Key 时提示并使用随应用打包的低分辨率底图；在线瓦片失败时检查 Key、访问域名和网络，不会自动切换到 ion。校园建筑白模等业务图层仍保留各自的数据来源和署名。

使用 Cesium 时设置 `VITE_BASEMAP_PROVIDER=cesium`，填写 `VITE_CESIUM_ION_TOKEN`；Token 留空则使用本地低分辨率底图和椭球地表。

这些配置会打包到浏览器端，真实 Key / Token 仅写入本机 `.env.local`，不要提交到仓库。修改后重启开发服务；生产部署需重新构建。

前端开发与预览通过同源代理将 `/api`、`/data-files` 转发到 `127.0.0.1:8000`。服务绑定回环地址，当前应用按本机单用户使用，未提供登录和多用户权限。

### 3. 停止与再次启动

在对应服务终端按 `Ctrl+C`。再次启动复用相同配置和启动命令；依赖没有变化时可跳过安装。SQLite、上传文件、场景与历史运行保存在存储目录，服务停止后保留。

## 构建与本机预览

保持后端运行，在前端目录执行：

```powershell
Set-Location D:\city\map
pnpm build
pnpm preview --port 4173 --strictPort
```

打开[构建预览](http://127.0.0.1:4173/)。构建产物位于 `map/dist/`；预览通过 Vite 提供静态文件和后端代理。`/cesium/` 下的 Workers、ThirdParty、Assets 和 Widgets 需完整保留，路径配置见 [vite.config.ts](../map/vite.config.ts)。

## 后端配置与持久数据

| 配置 | 默认值或作用 |
| --- | --- |
| `MAP_STORAGE_DIR` | 默认 `map_back/storage/`，存放数据库、上传文件和运行镜像 |
| `MAP_DATABASE_URL` | 默认使用存储目录下的 SQLite `catalog.db`；可覆盖连接地址 |
| `VITE_CESIUM_ION_TOKEN` | 前端 `.env.local` 中的浏览器可见配置 |

后端通过进程环境变量读取配置，`.env.example` 仅提供示例，服务不会自动加载 `.env`。自定义存储时，在运行迁移和启动服务的终端中使用相同配置：

```powershell
$env:MAP_STORAGE_DIR = 'D:\city\map_back\storage'
# 仅在需要覆盖默认数据库位置时设置；与存储目录保持一致。
$env:MAP_DATABASE_URL = 'sqlite:///D:/city/map_back/storage/catalog.db'
```

默认存储布局：

```text
map_back/storage/
├── catalog.db                 # 资产、登记、场景、收藏、运行及版本数据
├── files/<id>/...             # 上传资源，经 /data-files/ 发布
├── tmp/<id>/...               # 上传与下载的临时内容
├── deleting/<id>/...          # 删除暂存，失败可重试
└── runs/<run_id>/
    ├── input.json             # 不可变输入镜像
    ├── result.json            # 成功结果镜像
    └── run.log                # 日志镜像
```

默认校区资源仍位于 `map/public/samples/`，由后端按白名单提供 `/samples/` 入口。运行镜像通过运行 API 访问，数据库是运行记录的依据。

## 大文件导入与反向代理

GeoJSON 最大 1 GiB（1,073,741,824 字节）；3D Tiles ZIP 仍为 512 MiB。上传接口同步等待接收、校验、索引和原子发布后返回图层登记。传输结束后仍可能长时间处理，客户端分别显示传输进度及处理阶段。

受管 GeoJSON 使用流式解析、分块摘要与批量索引，主要内存开销取决于最大单个要素及固定批次。磁盘需同时容纳原文件、上传/编辑临时文件、SQLite 对象与空间索引及 WAL；索引中还保存几何、属性和检索文本，容量可能为源文件数倍。POI 编辑发布新快照并保留旧资产，须为新旧文件及索引同时预留空间。按照实际数据测试磁盘增长，不以 1 GiB 文件大小作为全部容量预算。

SQLite 启用 WAL，大文件导入串行写入；地图读取已提交的旧快照，文件与索引成功后才切换图层绑定。运行迁移时建立并回填 RTree 空间索引。备份 SQLite 时使用下文的停服备份流程，不能在服务写入期间只复制 `catalog.db` 而遗漏未 checkpoint 的 WAL。

使用 Nginx 等反向代理时，HTTP 请求体需为 multipart 边界预留额外空间。以下为配置起点，**超时最终值须由实际 1 GiB 样本的上传和导入耗时决定**；配置示例不代表一小时内完成的性能承诺：

```nginx
location /api/ {
    proxy_pass http://127.0.0.1:8000;
    client_max_body_size 1100m;
    client_body_timeout 3600s;
    proxy_read_timeout 3600s;
    proxy_send_timeout 3600s;
}
```

代理启用请求缓冲时还需预留代理临时文件空间。其他网关、隧道或 CDN 的上传限制与空闲超时也须覆盖此链路。浏览本地已索引图层使用受控视野响应，不应下载整份 GeoJSON；下载原文件属于显式资源导出操作。外部 URL 未新增服务端下载与索引。

## 升级、备份与恢复

### 升级与备份

1. 停止前后端，记录当前源码版本及自定义配置。
2. 备份完整存储目录，保留与备份匹配的源码和内置样例。
3. 更新代码后安装依赖，执行 `alembic upgrade head`，再启动服务。
4. 检查健康状态、旧资产、场景和历史运行，再验证地图加载。

默认目录的备份示例，在服务停止后执行：

```powershell
$storagePath = 'D:\city\map_back\storage'
$backupRoot = 'D:\city\backups'
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
$backupPath = Join-Path $backupRoot ('storage-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
if (Test-Path -LiteralPath $backupPath) { throw '备份目录已存在，请使用新目录。' }
Copy-Item -LiteralPath $storagePath -Destination $backupPath -Recurse -ErrorAction Stop
Get-Item -LiteralPath (Join-Path $backupPath 'catalog.db')
```

自定义存储时替换 `$storagePath`；如果数据库由 `MAP_DATABASE_URL` 指向其他位置，连同该数据库一并备份。数据库和资源文件需来自同一次停服备份。

### 恢复

保持服务停止，选择备份路径，将当前存储改名留存后恢复：

```powershell
$storagePath = 'D:\city\map_back\storage'
$restoreSource = Read-Host '输入待恢复的完整 storage 备份目录'
if (-not (Test-Path -LiteralPath (Join-Path $restoreSource 'catalog.db'))) {
    throw '所选备份缺少 catalog.db。'
}
if (Test-Path -LiteralPath $storagePath) {
    Rename-Item -LiteralPath $storagePath -NewName ('storage-before-restore-' + (Get-Date -Format 'yyyyMMdd-HHmmss')) -ErrorAction Stop
}
Copy-Item -LiteralPath $restoreSource -Destination $storagePath -Recurse -ErrorAction Stop
```

恢复匹配的源码和内置样例，设置相同环境变量后启动。用新代码读取旧备份时先执行迁移；回退代码则恢复与该代码匹配的备份。迁移降级可能删除运行、时序或工作区收藏等新增数据，日常恢复采用完整备份。

## 运行恢复与对账

服务正常停止时中断运行并记录 `SERVICE_STOPPED`；异常退出后，重启将遗留 `running` 标记为 `failed/RUN_INTERRUPTED`，继续处理 `queued`。单次模型计算超过 60 秒终止并记录 `RUN_TIMEOUT`。

需要核对目录时使用数据页“扫描已有文件”；运行镜像缺失时执行：

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/runs/reconcile
```

对账可补齐缺失镜像，并报告已改动文件、孤立目录或结果。出现内容不一致时保留现场，先检查诊断信息与备份；发布文件的指纹和固定版本共同用于内容核验。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 5173、4173 或 8000 端口被占用 | 找到对应旧服务，在其终端停止后重启；代理当前固定指向 8000 |
| 后端提示缺表 | 确认在 `map_back/` 执行迁移，且迁移与服务环境变量相同 |
| 上传、登记或历史查询失败 | 检查 `/api/health` 和后端终端，复制页面的 `code/message/trace_id` 定位日志 |
| 在线底图或地形失败 | 天地图检查 Key、访问域名和网络，Key 留空使用本地底图；Cesium 检查 Token 权限和网络，Token 留空使用本地底图 |
| 行政边界失败 | 检查 DataV 网络请求，点击重试；本地地区参考点仍可用于定位 |
| `/cesium/` 返回 404 或 HTML | 检查构建静态资源和 `CESIUM_BASE_URL`，通过 Vite 开发或预览命令访问 |
| 外部资源登记成功但加载失败 | 检查远端 URL、浏览器跨域许可及 3D Tiles 相对资源完整性 |
| 上传返回 413 或 422 | 按具体错误检查体积、GeoJSON 坐标、ZIP 路径及入口；规则见数据说明 |
| 删除返回 403 或 409 | 403 检查默认资源保护；409 查看图层、场景和历史运行引用 |
| 场景保存冲突 | 保留草稿，读取服务器最新版本后重新编辑保存 |
| 运行提交结果未知 | 使用“重试同一次提交”，保持原幂等键和输入 |
| 白模高度或位置异常 | 核对数据高度依据、地形采样和坐标；模型整体偏移见数据与模型说明 |

测试和核心操作验证见[开发说明](开发说明.md)，字段与错误规则见[接口说明](api_contract.md)。

## GeoJSON 完整快照与原文件保留

升级前备份目录数据库和 `storage/`，然后在后端目录运行现有 Alembic 升级命令。迁移 `0014_geojson_snapshot` 增加完整快照元数据；旧版本由后台处理时从原文件补齐，并逐项核对要素顺序、属性、几何和版本校验和。补齐失败的版本保留上传文件，排查错误后重试切片。

完整数据保存在目录数据库，`storage/files/` 保存上传文件，`storage/renders/{key}/` 保存已发布 PMTiles 和清单。备份须同时覆盖数据库及正式产物。不能将七天原文件清理理解为删除完整数据，也不能只备份 `storage/files/` 后清空数据库。

后端通过 `CITY_TILE_SERVICE_URL` 连接独立切片服务，以 `CITY_TILE_TOKEN` 发送内部凭据。默认由 Windows 主动流式推送完整快照，WSL 无需回连 Windows。`CITY_TILE_BACKEND_ORIGIN` 标识输入来源，使用拉取模式时还需保证该地址可达。也可在 `storage/tile-service.json` 设置 `url/token/backend`，同名环境变量优先。凭据只放在服务端，不写入前端配置。公开导出使用 `/api/assets/{asset_id}/versions/{version}/geojson`。

只有符合条件的上传 GeoJSON 完成完整快照验证并首次成功发布显示产物后，才开始该版本七天原文件保留期。后台在启动时补查，随后按北京时间每日 03:00 检查。文件先移入 `storage/expired-sources/`，提交到期状态后删除；启动恢复会根据数据库状态还原未提交的移动，或完成已提交的删除。不要手工清空此暂存目录。

到期后，上传原文件下载返回 410 `SOURCE_EXPIRED`，用户可继续导出完整 GeoJSON。正式数据导出的空白、字段顺序等可与上传文件不同，上传审计摘要不用于校验导出字节。发生切片失败、服务暂不可用或排队时，地图通过同版本视野接口显示。

反向代理需放行 PMTiles 的 `Range` 请求及 `Content-Range/Accept-Ranges/ETag` 响应头，禁止给 PMTiles 归档整体增加 gzip 编码。显示产物传输和完整 GeoJSON 输入为流式请求，应为大文件配置足够的超时和工作磁盘；当前后端接收的解包产物上限为 16 GiB，实际峰值还包含上传文件、数据库、传输归档与发布暂存。
