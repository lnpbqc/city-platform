# 部署说明

## 环境与目录

本文覆盖 Windows 本机单用户运行，使用 PowerShell，命令以项目位于 `D:\city` 为例。其他位置替换该路径，并保持 `map/`、`map_back/` 为同级目录。

准备 Node.js 24、pnpm、Python 3.13 和 uv。首次安装依赖需要联网；在线 Cesium 影像、地形和行政区边界也依赖网络。浏览器需支持 WebGL。

后端读取 `map/public/samples/` 和 `map/src/data/` 的内置资源，迁移或复制项目时保留完整前后端目录。`map/docs/research/` 的原始快照供离线生成白模和相关测试使用。

## 首次启动

### 1. 启动后端

打开第一个 PowerShell 终端：

```powershell
Set-Location D:\city\map_back
uv sync --no-dev
uv run --no-dev alembic upgrade head
uv run --no-dev uvicorn app.main:app --host 127.0.0.1 --port 8000
```

首次安装和升级代码后执行迁移，应用启动前需已有业务表。后端采用单个 uvicorn 服务进程，每次模型计算使用独立子进程；保持上述单进程启动方式。

在另一个终端检查：

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

预期返回 `status: ok`。接口入口为[交互文档](http://127.0.0.1:8000/docs)和[OpenAPI JSON](http://127.0.0.1:8000/openapi.json)。

### 2. 配置并启动前端

打开第二个 PowerShell 终端：

```powershell
Set-Location D:\city\map
pnpm install --store-dir ..\.pnpm-store
if (-not (Test-Path -LiteralPath .env.local)) {
    Copy-Item -LiteralPath .env.example -Destination .env.local
}
# 编辑 .env.local，配置 VITE_CESIUM_ION_TOKEN。
pnpm dev --port 5173 --strictPort
```

浏览器打开[地图工作台](http://127.0.0.1:5173/)。`VITE_CESIUM_ION_TOKEN` 填写具备所需影像和地形权限的浏览器只读 Token，修改后重启前端。使用随应用打包的低分辨率底图时，将值留空。

前端开发与预览通过同源代理将 `/api`、`/data-files` 转发到 `127.0.0.1:8000`。服务绑定回环地址，当前应用按本机单用户使用，未提供登录和多用户权限。

### 3. 停止与再次启动

在对应服务终端按 `Ctrl+C`。再次启动复用相同配置和启动命令；依赖没有变化时可跳过安装。SQLite、上传文件、场景与历史运行保存在存储目录，服务停止后保留。

## 构建与本机预览

保持后端运行，在前端目录执行：

```powershell
Set-Location D:\city\map
pnpm build
pnpm preview --port 4173 --strictPort
```

打开[构建预览](http://127.0.0.1:4173/)。构建产物位于 `map/dist/`；预览通过 Vite 提供静态文件和后端代理。`/cesium/` 下的 Workers、ThirdParty、Assets 和 Widgets 需完整保留，路径配置见 [vite.config.ts](../map/vite.config.ts)。

## 后端配置与持久数据

| 配置 | 默认值或作用 |
| --- | --- |
| `MAP_STORAGE_DIR` | 默认 `map_back/storage/`，存放数据库、上传文件和运行镜像 |
| `MAP_DATABASE_URL` | 默认使用存储目录下的 SQLite `catalog.db`；可覆盖连接地址 |
| `VITE_CESIUM_ION_TOKEN` | 前端 `.env.local` 中的浏览器可见配置 |

后端通过进程环境变量读取配置，`.env.example` 仅提供示例，服务不会自动加载 `.env`。自定义存储时，在运行迁移和启动服务的终端中使用相同配置：

```powershell
$env:MAP_STORAGE_DIR = 'D:\city\map_back\storage'
# 仅在需要覆盖默认数据库位置时设置；与存储目录保持一致。
$env:MAP_DATABASE_URL = 'sqlite:///D:/city/map_back/storage/catalog.db'
```

默认存储布局：

```text
map_back/storage/
├── catalog.db                 # 资产、登记、场景、收藏、运行及版本数据
├── files/<id>/...             # 上传资源，经 /data-files/ 发布
├── tmp/<id>/...               # 上传与下载的临时内容
├── deleting/<id>/...          # 删除暂存，失败可重试
└── runs/<run_id>/
    ├── input.json             # 不可变输入镜像
    ├── result.json            # 成功结果镜像
    └── run.log                # 日志镜像
```

默认校区资源仍位于 `map/public/samples/`，由后端按白名单提供 `/samples/` 入口。运行镜像通过运行 API 访问，数据库是运行记录的依据。

## 升级、备份与恢复

### 升级与备份

1. 停止前后端，记录当前源码版本及自定义配置。
2. 备份完整存储目录，保留与备份匹配的源码和内置样例。
3. 更新代码后安装依赖，执行 `alembic upgrade head`，再启动服务。
4. 检查健康状态、旧资产、场景和历史运行，再验证地图加载。

默认目录的备份示例，在服务停止后执行：

```powershell
$storagePath = 'D:\city\map_back\storage'
$backupRoot = 'D:\city\backups'
New-Item -ItemType Directory -Path $backupRoot -Force | Out-Null
$backupPath = Join-Path $backupRoot ('storage-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
if (Test-Path -LiteralPath $backupPath) { throw '备份目录已存在，请使用新目录。' }
Copy-Item -LiteralPath $storagePath -Destination $backupPath -Recurse
Get-Item -LiteralPath (Join-Path $backupPath 'catalog.db')
```

自定义存储时替换 `$storagePath`；如果数据库由 `MAP_DATABASE_URL` 指向其他位置，连同该数据库一并备份。数据库和资源文件需来自同一次停服备份。

### 恢复

保持服务停止，选择备份路径，将当前存储改名留存后恢复：

```powershell
$storagePath = 'D:\city\map_back\storage'
$restoreSource = Read-Host '输入待恢复的完整 storage 备份目录'
if (-not (Test-Path -LiteralPath (Join-Path $restoreSource 'catalog.db'))) {
    throw '所选备份缺少 catalog.db。'
}
if (Test-Path -LiteralPath $storagePath) {
    Rename-Item -LiteralPath $storagePath -NewName ('storage-before-restore-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
}
Copy-Item -LiteralPath $restoreSource -Destination $storagePath -Recurse
```

恢复匹配的源码和内置样例，设置相同环境变量后启动。用新代码读取旧备份时先执行迁移；回退代码则恢复与该代码匹配的备份。迁移降级可能删除运行、时序或工作区收藏等新增数据，日常恢复采用完整备份。

## 运行恢复与对账

服务正常停止时中断运行并记录 `SERVICE_STOPPED`；异常退出后，重启将遗留 `running` 标记为 `failed/RUN_INTERRUPTED`，继续处理 `queued`。单次模型计算超过 60 秒终止并记录 `RUN_TIMEOUT`。

需要核对目录时使用数据页“扫描已有文件”；运行镜像缺失时执行：

```powershell
Invoke-RestMethod -Method Post http://127.0.0.1:8000/api/runs/reconcile
```

对账可补齐缺失镜像，并报告已改动文件、孤立目录或结果。出现内容不一致时保留现场，先检查诊断信息与备份；发布文件的指纹和固定版本共同用于内容核验。

## 常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 5173、4173 或 8000 端口被占用 | 找到对应旧服务，在其终端停止后重启；代理当前固定指向 8000 |
| 后端提示缺表 | 确认在 `map_back/` 执行迁移，且迁移与服务环境变量相同 |
| 上传、登记或历史查询失败 | 检查 `/api/health` 和后端终端，复制页面的 `code/message/trace_id` 定位日志 |
| 在线底图或地形失败 | 检查 Token 权限和网络；留空 Token 可使用本地低分辨率底图 |
| 行政边界失败 | 检查 DataV 网络请求，点击重试；本地地区参考点仍可用于定位 |
| `/cesium/` 返回 404 或 HTML | 检查构建静态资源和 `CESIUM_BASE_URL`，通过 Vite 开发或预览命令访问 |
| 外部资源登记成功但加载失败 | 检查远端 URL、浏览器跨域许可及 3D Tiles 相对资源完整性 |
| 上传返回 413 或 422 | 按具体错误检查体积、GeoJSON 坐标、ZIP 路径及入口；规则见数据说明 |
| 删除返回 403 或 409 | 403 检查默认资源保护；409 查看图层、场景和历史运行引用 |
| 场景保存冲突 | 保留草稿，读取服务器最新版本后重新编辑保存 |
| 运行提交结果未知 | 使用“重试同一次提交”，保持原幂等键和输入 |
| 白模高度或位置异常 | 核对数据高度依据、地形采样和坐标；模型整体偏移见数据与模型说明 |

测试和核心操作验证见[开发说明](开发说明.md)，字段与错误规则见[接口说明](api_contract.md)。
