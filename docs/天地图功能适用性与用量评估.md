# 天地图功能适用性与用量评估

评估日期：2026年11月19日。

天地图适合提供底图、公共地名搜索、行政区边界和地址补全。按10人、每人每天高频使用约2小时估算，个人开发者的底图额度存在明显超额风险，交互式搜索和地址查询的压力较小。

## 当前接入状态

当前本地配置默认使用 Cesium 影像。平台已支持天地图影像、矢量底图及中文矢量注记；本次增加中文影像注记、独立注记开关、最高瓦片层级配置和底图实例复用。当前状态以运行环境配置和浏览器保存的选择为准。

行政区名称搜索使用本地目录，边界来自阿里云；附近 POI 查询使用本地数据，地址由人工填写。道路阻断仿真使用本地固定路网和 Dijkstra 算法。下表中的候选 Web 服务尚未接入。

## 配额与估算口径

配额取自用户提供的天地图截图。全国服务的最新扣额规则、并发限制、按账号或应用聚合的范围，需要对照申请 Key 时的规则和控制台统计核实；本次访问官方开发文档超时，未独立确认这些规则。

| 个人开发者服务 | 截图日配额 |
| --- | ---: |
| 影像底图、矢量底图、矢量注记、影像注记、地形晕渲、地形注记、矢量英文注记、影像英文注记、全球境界、三维地名、三维地形 | 每项10000次 |
| 静态地图、行政区划服务、公交规划、驾车规划、地图搜索 | 每项3000次 |
| 地理编码、逆地理编码 | 每项7000次 |

容量预算按10名日活跃使用者共享同一账号、每人每天约100次明显平移、缩放或地区切换计算。瓦片按一次请求消耗一次调用的保守口径估算，各项服务分别核算，不将不同服务的剩余额度直接相加。

以下数值是预算假设，不是访问日志或天地图控制台的实测统计。项目目前仍按本机单用户部署；10人是本次容量评估场景，不表示平台已支持团队账号及权限。

地图搜索与附近 POI 合计约400次/日，占截图3000次额度的约13%；分页、输入联想、失败重试会额外增加调用。地理编码约占7000次额度的1.4%，逆地理编码约占2.9%。批量地址导入需另行按地址条数计算。

建筑模型、道路显示与阻断计算、框选统计、专题时间轴、历史回放、数据管理、天气效果和自有 POI 标签由现有数据、算法或其他服务提供，不需要额外接入表中服务。地图视野变化导致的底图加载仍计入底图预算，不能再按这些业务功能重复累计。

## 底图估算公式与额度风险

Cesium 通过 WMTS 按瓦片请求地图，不按页面打开次数请求整幅地图。预算采用每次明显视野变化、每层新增30～100张瓦片的假设：

`10人 × 100次明显视野变化/人/日 × 30～100张瓦片/次/层 = 3万～10万次/日/层`

30～100张不是实测值，也不是上限。重复查看固定区域可能减少新增请求，跨城飞行、三维倾斜、连续缩放、浏览器刷新和失败重试可能增加请求。缓存是否命中取决于浏览器、服务响应和 Cesium 的资源回收。

| 使用场景 | 各服务预计日用量 | 对个人额度的影响 |
| --- | ---: | --- |
| 全天使用天地图影像，注记关闭 | 影像3万～10万 | 约为影像额度的3～10倍 |
| 全天使用天地图矢量及注记 | 矢量、矢量注记各3万～10万 | 两项分别可能超额 |
| 天地图影像、矢量各使用一半，影像注记关闭 | 影像、矢量、矢量注记各1.5万～5万 | 仍可能超额 |
| 保留 Cesium 影像，仅部分使用天地图矢量 | 按矢量使用比例计算 | 重点核对矢量和矢量注记 |
| 额外开启影像注记 | 增加与影像视野接近的注记请求 | 使用独立影像注记额度 |

## 本次优化及实测边界

- `VITE_TIANDITU_MAX_LEVEL` 控制天地图底图及注记的最高层级，默认18，允许1～18的整数；空值和非法值回退18。设置16后仍可继续放大地图，但影像细节受限。Cesium 影像、自有模型和地形不受此项设置影响。开发时修改后重启前端；部署时重新构建。
- 底图和注记按需创建，本页内切换时隐藏并复用原实例。关闭注记或隐藏底图后不加载新视野，已经发出的请求可能继续完成。当前安装的 Cesium 在图层隐藏后释放其瓦片资源，切回时的网络请求取决于浏览器 HTTP 缓存；实例复用不保证减少瓦片调用量。源码依据为 Cesium engine 的 `GlobeSurfaceTileProvider._onLayerShownOrHidden` 和 `Imagery.releaseReference`。
- 不增加持久化瓦片缓存、批量预取、离线下载、后端代理或镜像。授权和使用范围以所用全国服务及 Key 的条款为准。
- 层级限制和复用的节省比例需要相同视口、相机路径、服务及缓存条件下对比，不预填降低后的日用量。请求量实验另存为 `output/playwright/tianditu-usage-comparison.json`，同时记录环境和测量方式；受控响应实验只验证请求调度，不等同于天地图真实扣额。

## 请求调度验证记录

2026年11月19日，使用 Edge 无界面浏览器，在1440×1000视口、椭球地表和垂直俯视条件下，对相同六个相机位置进行对比。高度依次为4000、1000、250、100米，随后在100米高度平移两次。每个场景使用新页面，等待相机更新及瓦片加载结束；拦截天地图请求并返回本地生成的256×256 PNG，不访问天地图服务器。此实验关闭 HTTP 缓存，验证的是当前 Cesium 的请求调度。

| 最高层级 | 影像注记 | 影像请求 | 注记请求 | 合计 |
| --- | --- | ---: | ---: | ---: |
| 18 | 关闭 | 152 | 0 | 152 |
| 18 | 开启 | 152 | 152 | 304 |
| 16 | 关闭 | 104 | 0 | 104 |
| 16 | 开启 | 104 | 104 | 208 |

这条固定路径中，最高层级从18改为16后，影像请求减少48次，约31.6%；开启注记增加了与影像相同数量的请求。两个开启注记的场景均在关闭注记后继续平移，新增注记请求为0。最高实际请求层级分别为18和16，实验没有脚本异常。

这些结果不测量真实影像下载速度、线上缓存命中或天地图扣额，也不用于改写前文的日用量估算。不同视野路径和浏览强度会产生不同结果。原始记录：`output/playwright/tianditu-usage-comparison.json`。
